# Foray UI Specification

> 문서 상태: MVP UI 기준 최신 확정본  
> 마지막 정리일: 2026-07-22  
> 목적: 화면 상태, 배치, 입력 규칙, 데이터 반영 시점을 구현 전에 고정한다.

---

## 1. 공통 UI 원칙

### 1.1 MVP 우선순위

1. 화면 상태 전환
2. 필요한 데이터 표시
3. 입력 가능 대상 구분
4. 클릭·선택·드래그·확정 흐름
5. 화면 전환 시 임시 상태 초기화
6. 시각적 완성도와 애니메이션

MVP에서는 정확한 픽셀, 색상, 폰트보다 화면 계층과 상호작용을 우선한다.

### 1.2 데이터 변경 원칙

- Hover는 실제 게임 데이터를 변경하지 않는다.
- 클릭 선택은 임시 상태이며 실제 게임 데이터를 변경하지 않는다.
- 구매, 판매, 카드 사용, 증강 획득·교체, 배치는 확정된 동작에서만 실제 데이터에 반영한다.
- 드래그 실패 또는 유효하지 않은 Drop은 원위치 복귀하며 실제 데이터는 변경하지 않는다.
- 화면 상태가 전환되면 선택, Hover, Tooltip, Drag, DropZone 표시를 초기화한다.
- UI 클래스는 `RunManager`, `Shop`, `BattleManager`, 카드 시스템 등의 공개 메서드를 통해 데이터를 변경한다.
- 모달 또는 비전투 상태에서는 시각적 입력 차단과 `RunState` 검사를 함께 사용한다.
- 사용 버튼과 Drag & Drop은 같은 검증·실행 메서드를 호출한다.

## 2. 전체 런 화면 흐름

```text
Title
  ↓
Run Start
  ↓
Deployment
  ↓
Battle
  ↓
Battle Result
  ├─ Normal Victory → Shop
  ├─ Boss Victory → Augment Selection
  │                   ├─ 보유 5개 미만 → 획득 → Shop
  │                   └─ 보유 5개 → Augment Replacement → Shop
  ├─ King Defeated → Run Over
  └─ Final Victory → Run Clear

Shop
  ├─ 기물 구매·판매·재배치
  ├─ 최대 인구 구매
  └─ 카드 상자 구매 → CardSelection → 기존 Shop 복귀
  ↓
Leave Shop
  ↓
다음 전투용 새 Board 생성
  ↓
적 전체 공개
  ↓
아군 자동 배치
  ↓
Deployment
  ↓
전투 시작 버튼
  ↓
Battle
```

## 3. 기본 런 화면 레이아웃

### 3.1 Battle 상태

```text
┌──────────────────────────────────────────────────────────────┐
│ 보유 증강                 Stage / Round               Gold   │
│                                                              │
│ ┌──────────┐       ┌──────────────────────┐    ┌──────────┐ │
│ │ 증강 1   │       │                      │    │ 카드 1   │ │
│ │ 증강 2   │       │        Board         │    │ 카드 2   │ │
│ │ 증강 3   │       │                      │    │ 카드 3   │ │
│ │ 증강 4   │       └──────────────────────┘    └──────────┘ │
│ │ 증강 5   │          현재 보유 기물 요약                    │
│ └──────────┘                                                 │
└──────────────────────────────────────────────────────────────┘
```

고정 영역:

- 보유 증강: 화면 왼쪽 가장자리
- Stage / Round: 화면 중앙 상단
- Gold: 화면 오른쪽 상단
- 보유 카드: 화면 오른쪽 가장자리

상태에 따라 이동하는 영역:

- Board
- Board 아래의 보유 기물 요약

Battle에서는 Board가 화면 중앙에 위치한다.

### 3.2 Shop 상태

```text
┌──────────────────────────────────────────────────────────────┐
│ 보유 증강                 Stage / Round               Gold   │
│                                                              │
│ ┌──────────┐ ┌─────────────────┐ ┌──────────────┐ ┌────────┐│
│ │ 증강 1   │ │                 │ │              │ │ 카드 1 ││
│ │ 증강 2   │ │      Board      │ │     Shop     │ │ 카드 2 ││
│ │ 증강 3   │ │                 │ │              │ │ 카드 3 ││
│ │ 증강 4   │ └─────────────────┘ │              │ └────────┘│
│ │ 증강 5   │    보유 기물 요약    └──────────────┘           │
│ └──────────┘                                                 │
└──────────────────────────────────────────────────────────────┘
```

Shop 진입 시:

- Board와 보유 기물 요약만 왼쪽으로 이동
- 보유 증강은 고정
- Stage / Round는 고정
- Gold는 고정
- 보유 카드는 고정
- Board와 보유 카드 사이에 ShopPanel 표시
- Board는 전체가 계속 보여야 한다

Shop 종료 후:

- ShopPanel 숨김
- Board와 기물 요약 중앙 복귀
- 다음 전투용 새 Board 생성
- Deployment 상태 진입

## 5. 전투 화면

### 5.1 기본 상태

- ShopPanel 숨김
- 모달 숨김
- Board는 중앙의 전투용 크기
- 선택된 기물 없음
- 이동 가능 칸 하이라이트 없음
- 플레이어 입력 가능
- StartBattleButton 숨김

### 5.2 Board 크기

- 5×5, 7×7, 9×9, 11×11 Board 전체가 화면에 보여야 한다.
- Board는 정사각형 비율을 유지한다.
- 일부 셀이 화면 밖으로 잘리면 안 된다.

### 5.3 일반 Battle 입력

1. 플레이어 기물 클릭
   - 기물 선택
   - 기물 확대
   - 이동 가능 칸 표시

2. 선택된 기물 재클릭
   - 선택 해제
   - 확대 해제
   - 하이라이트 제거

3. 다른 플레이어 기물 클릭
   - 선택 전환
   - 이동 가능 칸 갱신

4. 이동 가능한 빈 칸 또는 포획 가능한 적 클릭
   - 행동 실행
   - 선택 초기화
   - 적 턴 실행
   - 화면 갱신

5. 이동 불가능한 위치 클릭
   - 게임 데이터 변경 없음
   - 필요 시 선택만 해제

### 5.4 카드 대상 선택과 이동 선택 구분

전투 중 기물 선택은 다음 두 목적을 구분해야 한다.

```text
일반 Battle 선택
→ 이동할 기물 선택

대상 지정 카드 사용 준비
→ 카드 효과 대상 기물 선택
```

두 상태를 하나의 선택 변수로 함께 관리하지 않는다.

### 5.5 입력 차단

다음 상황에서는 일반 Battle 입력을 막는다.

- 전투 결과 UI 표시 중
- Shop
- Deployment
- CardSelection
- AugmentSelection
- AugmentReplacement
- 적 AI 행동 중
- Drag & Drop 처리 중

## 6. 전투 결과 UI

### 6.1 표시

- 기존 전투 화면 위에 `ResultWindow` 표시
- Victory 또는 Defeat 표시
- 결과 UI 표시 중 Board 입력 차단

### 6.2 적 왕 처치 후 정리

```text
적 왕 처치
→ 승리 확정
→ 남아 있는 적 기물 모두 사망 처리
→ Board에서 적 기물 제거
→ 살아남은 아군 기물 위치 유지
→ 전투 결과 UI
```

전투 중 사망한 영구 아군은 `PlayerArmy`에는 남아 있으며 Shop 진입 시 Board에 복귀시킨다.

### 6.3 Continue

- 일반전 승리 → Shop
- 보스전 승리 → AugmentSelection
- 왕 사망 → Run Over
- 최종 전투 승리 → Run Clear

## 7. 보유 증강 UI

### 7.1 표시

- 화면 왼쪽 가장자리
- 세로 정렬
- 최대 5개
- 패널과 빈 슬롯을 항상 표시
- 실제 증강은 위에서 아래로 채움
- 빈 슬롯은 흐린 배경
- 빈 슬롯에 `+`, `Empty` 등의 텍스트를 표시하지 않음
- 빈 슬롯 Hover·Click·Tooltip 없음

### 7.2 Hover

- 카드 확대
- Tooltip 표시
- 이름과 효과 설명 표시
- Hover 종료 시 클릭 고정 상태가 있으면 그 상태로 복귀

### 7.3 Click

- 선택되지 않은 카드 클릭 → 확대와 Tooltip 고정
- 같은 카드 재클릭 → 선택 해제
- 다른 카드 클릭 → 선택 전환

### 7.4 상태 전환

- Shop에서는 확인 가능
- AugmentSelection에서는 입력 차단
- AugmentReplacement에서는 기존 보유 증강 5개를 교체 대상으로 조작 가능
- 상태 전환 시 일반 선택·Hover·Tooltip 초기화

## 8. 보유 카드 UI

### 8.1 표시

- 화면 오른쪽 가장자리
- Gold 아래에서 시작
- 최대 3개
- 패널과 빈 슬롯을 항상 표시
- 카드는 위에서 아래로 채움
- 판매 또는 사용 후 남은 카드는 위로 당겨짐
- 빈 슬롯은 흐린 배경
- 빈 슬롯 Hover·Click·Tooltip 없음

### 8.2 Hover

- 카드 확대
- Tooltip 표시
- Tooltip에는 이름, 설명, 사용 조건, 사용 시점 표시
- Tooltip 위치는 Inspector에서 조정

### 8.3 Click

- 카드 클릭 → 확대와 Tooltip 고정
- 선택된 카드 아래에 `사용` 버튼 표시
- 같은 카드 재클릭 → 선택 해제
- 다른 카드 클릭 → 선택 전환
- 사용 불가 상태에서도 선택은 가능하지만 사용 시도는 실패 처리

### 8.4 사용 불가 피드백

사용 시점이 아니거나 조건을 만족하지 못하면:

- 카드 사용 처리하지 않음
- Drag 중 Board Drop Overlay를 회색 또는 비활성 상태로 표시
- 사용 버튼은 비활성 상태로 표시
- Drop 시 카드는 원래 슬롯으로 복귀
- 실제 데이터 변경 없음
- 중앙 공용 메시지는 표시하지 않음

불가 이유는 카드 자체 상태, 사용 버튼, Tooltip 또는 Drop Overlay 중 가장 가까운 UI에서만 표현한다.

## 9. 카드 사용

### 9.1 사용 시점

기존 코어 로직의 `CardUseTiming`을 그대로 사용한다.

- `OnAcquire`
- `BeforeBattle`
- `BeforePlayerAction`
- `Anytime`
- 기존 코드에 정의된 추가 Timing이 있으면 그대로 활용

### 9.2 입력 방식

카드는 두 방식으로 사용한다.

```text
카드 클릭
→ 사용 버튼 클릭
```

```text
카드 드래그
→ Board 사용 영역에 드롭
```

두 입력은 동일한 `CanUseCard` / `TryUseCard` 계열 로직을 호출한다.

### 9.3 대상이 없는 카드

예: 다음 전투 동안 최대 인구 증가

```text
카드 선택 또는 드래그
→ 사용 조건 검사
→ 효과 적용
→ 카드 제거
→ 보유 카드 UI 재정렬
```

### 9.4 대상이 필요한 카드

대상 기물을 먼저 선택한다.

```text
대상 기물 선택
→ 카드 사용 버튼 클릭 또는 Board에 드롭
→ 대상 조건 검사
→ 효과 적용
```

대상이 없으면:

```text
대상을 먼저 선택하세요.
```

잘못된 대상이면:

```text
다른 대상을 선택하세요.
```

카드를 먼저 선택하는 것은 허용하지만, 유효한 대상이 없으면 사용되지 않는다.

### 9.5 카드 사용 DropZone

- Board 전체를 카드 사용 DropZone으로 사용
- 카드 드래그 중에만 Board와 같은 크기의 반투명 Overlay 표시
- 문구: `카드 사용`
- 사용 가능한 상태면 정상 강조
- 사용 불가능한 상태면 비활성 또는 금지 표현
- 실패 시 카드 원위치 복귀

## 10. 상점 화면

### 10.1 Shop 진입

- 기존 Board를 제거하지 않음
- BoardContentRoot를 왼쪽으로 이동
- Board 전체가 보이도록 필요 시 축소
- ShopPanel 표시
- Dim Overlay 사용하지 않음
- 보유 증강, 보유 카드, Stage/Round, Gold는 고정
- 상점 종료는 `Leave Shop` 버튼으로만 수행

### 10.2 전투 후 Shop Board 구성

Shop 진입 시 Board에는 다음만 남긴다.

- 살아남은 아군 기물: 전투 종료 위치 유지
- 남아 있던 적 기물: 모두 제거
- 전투 중 사망한 영구 아군: Board 하단 빈 셀부터 자동 복귀

복귀 배치 순서:

1. 가장 아래 행의 빈 셀
2. 같은 행 왼쪽 → 오른쪽
3. 아래 행이 가득 차면 그 위 행
4. 플레이어 측 영역이 가득 차면 나머지 Board 빈 셀

기존 생존 기물 위치는 바꾸지 않는다.

### 10.3 Shop 상태 Board 입력

Shop에서는 Board를 부대 정리 공간으로 사용한다.

가능:

- 기존 아군 기물 Drag 이동
- 다른 아군 기물과 Swap
- 기물 상품을 빈 셀에 Drop하여 구매
- 아군 기물을 SellDropZone에 Drop하여 판매

불가:

- 행마법에 따른 이동
- 턴 소모
- 적 기물 조작
- 전투 행동

Drop 결과:

| Drop 위치 | 결과 |
|---|---|
| Board 빈 셀 | 기물 이동 |
| 다른 아군이 있는 셀 | 두 기물 Swap |
| SellDropZone | 판매 시도 |
| Board 밖 일반 영역 | 원위치 복귀 |
| 유효하지 않은 UI | 원위치 복귀 |

## 11. ShopPanel 내부 구조

```text
ShopPanel
├ Background
├ Title
├ PieceShopArea
├ CardChestShopArea
├ BottomArea
│  ├ SellDropZone
│  └ PopulationPurchaseArea
└ LeaveShopButton
```

배치:

- 상단: 기물 상품
- 중단: 카드 상자 상품
- 하단 왼쪽: 판매 영역
- 하단 오른쪽: 최대 인구 구매
- 맨 아래: Leave Shop
- 스크롤 사용하지 않음

## 12. 기물 상품 UI

### 12.1 상품 구성

현재 해금된 기물 종류를 각각 1개씩 표시한다.

```text
런 시작: 졸, 마
포 해금 후: 졸, 마, 포
차 해금 후: 졸, 마, 포, 차
```

규칙:

- 해금되지 않은 기물은 표시하지 않음
- 같은 종류 중복 없음
- 같은 상점에서 종류별 한 번만 구매 가능
- 다음 상점에서는 다시 구매 가능
- 구매한 상품은 `Sold` 상태 유지
- 스크롤 없음

### 12.2 표시 정보

상시 표시:

- 기물 이미지
- 가격

Hover 또는 Click Tooltip:

- 기물 이름
- 인구 비용

Click:

- 기물 이미지 확대
- Tooltip 고정
- 같은 상품 재클릭 시 선택 해제
- 다른 상품 클릭 시 선택 전환

### 12.3 구매 방식

구매 버튼을 사용하지 않는다.

```text
기물 상품 Drag 시작
→ Board 위 구매 Overlay 표시
→ Board의 빈 셀에 Drop
→ 구매 조건 검사
→ 구매 성공
```

구매 조건:

- 현재 상태가 Shop
- 상품이 Sold가 아님
- 골드 충분
- 구매 후 `CurrentPopulation <= MaxPopulation`
- Drop한 셀이 Board 내부의 빈 셀

구매 성공:

1. Gold 차감
2. 고유 ID를 가진 영구 기물을 `PlayerArmy`에 추가
3. Drop한 셀에 실제 기물 배치
4. 상품 Sold 처리
5. 보유 기물 요약 갱신
6. BoardUI 갱신

구매 불가 또는 실패:

- Drag 중 Board Drop Overlay를 회색 또는 비활성 상태로 표시
- Drop 시 상품 원위치 복귀
- 구매 처리하지 않음
- 데이터 변경 없음
- 중앙 공용 메시지는 표시하지 않음

## 13. 기물 고유 ID

기물은 단순 `PieceType`만으로 식별하지 않는다.

개념 구조:

```text
ArmyPiece
- InstanceId
- PieceType
```

Board 위 `Piece`는 대응하는 `ArmyPiece.InstanceId`를 식별할 수 있어야 한다.

용도:

- 동일 종류 기물 개별 판매
- 카드 대상 유지
- 개별 강화·상태 효과
- 생존·복귀 추적
- Shop Board와 PlayerArmy 동기화

`PlayerArmy` 목록 인덱스만으로 개별 기물을 식별하지 않는다.

## 14. 기물 판매

### 14.1 기본 흐름

- Shop 상태에서만 가능
- Board 위 아군 기물을 직접 Drag
- SellDropZone은 Shop에서 활성화
- Drag 중 대상 이름과 판매가 표시
- Drop 즉시 판매
- 별도 확인창 없음

판매 성공:

1. 고유 ID 기준 `PlayerArmy`에서 제거
2. Board에서 제거
3. 판매 골드 지급
4. 보유 기물 요약 갱신
5. BoardUI 갱신

### 14.2 왕과 판매 불가 기물

왕도 Drag 자체는 가능하다.

왕 또는 판매 불가 기물을 Drag하면:

- SellDropZone을 회색 또는 비활성 상태로 표시
- 판매가 대신 `판매 불가` 상태를 표시할 수 있음
- Drop 시 판매 처리하지 않음
- Gold 변화 없음
- PlayerArmy 변화 없음
- 원래 셀로 복귀
- 중앙 공용 메시지는 표시하지 않음

증강이나 특수 상태로 판매 불가능한 기물도 같은 방식으로 처리한다.

- Drag 중 Board Drop Overlay를 회색 또는 비활성 상태로 표시
- Drop 시 상품 원위치 복귀
- 구매 처리하지 않음
- CardSelection으로 전환하지 않음
- 중앙 공용 메시지는 표시하지 않음

## 16. CardSelection

### 16.1 화면 상태

- ShopPanel 숨김
- 기존 Shop 데이터와 Sold 상태는 유지
- Dim Overlay 표시
- 카드 후보만 조작 가능
- 보유 카드 패널은 표시할 수 있으나 입력 차단
- 카드 판매 불가
- 카드 사용 불가
- 기물 판매 불가

### 16.2 보유 카드가 가득 찬 경우

보유 카드가 3/3이어도 카드 상자 구매는 허용한다.

- `OnAcquire` 카드는 선택 가능
- 일반 보유 카드는 슬롯이 가득 차 있으면 선택 불가
- 기존 카드를 판매해서 공간을 만들 수 없음
- 담을 수 있는 카드가 없거나 원하지 않으면 Skip

### 16.3 종료

- 선택 횟수를 모두 사용하면 기존 Shop으로 복귀
- Skip 시 남은 선택 횟수 전체 포기
- 새로운 Shop을 생성하지 않음
- 기존 상품 Sold 상태 유지
- ShopPanel 다시 표시

## 18. 최대 인구와 영구·임시 기물

### 18.1 영구 보유 기물

영구 보유 기물은 항상 다음을 만족해야 한다.

```text
CurrentPopulation <= MaxPopulation
```

검사 시점:

- 기물 구매
- 카드로 영구 기물 획득
- 기물 변환으로 인구 비용 증가
- 기타 영구 기물 추가 효과

초과하면 해당 구매 또는 카드 사용을 막는다.

### 18.2 카드로 무작위 기물 획득

- 남은 인구 안에서 획득 가능한 기물만 후보로 사용
- 결과가 최대 인구를 초과하면 카드 사용 불가
- 효과 적용 후 되돌리는 방식보다 실행 전 검증을 우선

### 18.3 임시 전투 기물

언데드 군주처럼 전투 중 일시적으로 생성되는 기물은:

- `PlayerArmy`에 추가하지 않음
- 최대 인구 계산에서 제외
- 현재 Battle에서만 존재
- 전투 종료 시 제거
- Shop과 Deployment에 따라오지 않음

## 19. 보유 기물 요약

Board 바로 아래에 `PlayerArmy` 기준 보유 기물과 인구 정보를 표시한다.

권장 Hierarchy:

```text
OwnedPieceSummaryPanel
├ PieceListRoot
│  └ PieceSummaryItemUI(Clone)
│     ├ PieceIcon
│     └ CountText
└ PopulationText
```

표시 규칙:

- 실제 보유 수가 1개 이상인 기물 종류만 표시
- 보유하지 않은 종류는 `포 0`, `차 0`처럼 표시하지 않음
- 표시 순서: 왕 → 졸 → 마 → 포 → 차
- 기물 요약은 패널 왼쪽에 고정
- 인구 정보는 패널 오른쪽에 고정
- 기물 종류별 항목은 Prefab으로 동적 생성
- 현재는 임시 이미지 또는 텍스트를 사용할 수 있으나 최종적으로 실제 기물 이미지를 사용
- 인구는 `현재 인구 / 최대 인구` 형식으로 표시
- 코드 내부 2배 단위는 플레이어에게 실제 수치로 변환하여 표시

예:

```text
[왕 이미지] 1   [졸 이미지] 2                  인구 3 / 3
```

갱신 시점:

- 런 시작
- 기물 구매
- 기물 판매
- 카드·증강으로 영구 기물이 추가 또는 제거될 때
- 최대 인구 구매
- 런 재시작
- 다음 전투 Board 생성

Board 위에 현재 살아 있는 기물 수가 아니라 `PlayerArmy`를 기준으로 한다.

## 21. Deployment

### 21.1 초기 자동 배치

- 모든 영구 보유 기물은 반드시 출전
- 출전 제외 기능 없음
- `PlayerArmy` 목록 순서대로 배치
- 배치 셀은 가장 아래 행부터 왼쪽 → 오른쪽
- 아래 행이 가득 차면 그 위 행
- 왕도 별도 예외 없이 목록 순서에 따라 배치

### 21.2 화면

```text
                 Stage / Round

              ┌───────────────┐
              │               │
              │     Board     │
              │               │
              └───────────────┘

             현재 보유 기물 요약

               [전투 시작]
```

- BoardContentRoot는 중앙
- StartBattleButton은 Board 아래
- 보유 기물 요약보다 더 아래에 표시
- Deployment 상태에서만 표시

### 21.3 배치 조작

- Drag & Drop 방식
- 플레이어 배치 가능 구역 안에서만 이동 가능
- 빈 셀에 Drop → 이동
- 다른 아군 기물 셀에 Drop → Swap
- 배치 구역 밖 Drop → 원위치 복귀
- 적 기물 이동 불가
- 행마법 적용 안 함
- 턴 소모 없음
- 판매 불가
- 카드 사용은 `CardUseTiming`에 따라 허용 여부 결정

### 21.4 전투 시작 버튼

정상적인 Deployment에서는 모든 기물이 자동으로 유효한 위치에 있으므로 기본 활성화 가능하다.

클릭 시 최종 검증:

- 현재 상태가 Deployment
- 모든 영구 보유 기물이 Board에 존재
- 모든 아군 기물이 플레이어 배치 가능 구역 안에 있음
- 같은 셀 중복 없음
- 왕이 존재함

성공 시:

```text
선택·Hover·Drag 상태 초기화
→ StartBattleButton 숨김
→ Battle 상태
```

## 25. 상태 기반 피드백

MVP에서는 중앙 공용 메시지 UI를 사용하지 않는다.

피드백 우선순위:

1. 조작 대상 자체의 상태 변화
2. DropZone 또는 버튼의 활성·비활성 상태
3. Tooltip의 불가 이유
4. 별도 중앙 메시지는 사용하지 않음

### 25.1 기물·카드 상자 구매

구매 가능:

- 가격과 상품을 정상 상태로 표시
- Drag 중 Board Drop Overlay를 활성 상태로 표시
- Drop 허용

구매 불가:

- 가격 또는 상품을 어둡게 표시할 수 있음
- Drag 중 Board Drop Overlay를 회색 또는 비활성 상태로 표시
- Drop 시 원위치 복귀
- 구매 처리하지 않음

### 25.2 카드 사용

사용 가능:

- 사용 버튼 활성
- Drag 중 Board Drop Overlay 활성
- Drop 또는 버튼 클릭 허용

사용 불가:

- 사용 버튼 비활성
- Drag 중 Board Drop Overlay 회색 또는 비활성
- Drop 시 원위치 복귀
- 카드 효과 실행하지 않음

### 25.3 기물 판매

판매 가능:

- SellDropZone 활성
- 대상 이름과 판매가 표시
- Drop 허용

판매 불가:

- SellDropZone 회색 또는 비활성
- `판매 불가` 상태 표시 가능
- Drop 시 원위치 복귀
- 판매 처리하지 않음

### 25.4 원칙

- 실패 이유를 화면 중앙에 반복 표시하지 않는다.
- 가능한 경우 조작 중인 대상과 가장 가까운 UI에서 상태를 표현한다.
- 입력이 실패해도 실제 게임 데이터는 변경하지 않는다.
- 공용 메시지 UI는 해금·특수 연출 등 별도 필요성이 생길 때 다시 검토한다.

## 30. 스파게티 방지 체크리스트

- [ ] 사용 버튼과 Drag 사용이 같은 카드 실행 로직을 호출하는가?
- [ ] Board의 기물과 PlayerArmy 기물이 고유 ID로 연결되는가?
- [ ] Shop의 기물 이동과 Battle의 행마 로직이 분리되는가?
- [ ] 카드 대상 선택과 Battle 이동 선택이 분리되는가?
- [ ] 화면 전환 시 선택·Hover·Tooltip·Drag가 초기화되는가?
- [ ] Board 입력이 `RunState` 검사로도 차단되는가?
- [ ] Dim Overlay의 Raycast Target이 필요한 입력을 막는가?
- [ ] Tooltip이 데이터 변경 책임을 갖지 않는가?
- [ ] Shop에서 Board 전체가 보이는가?
- [ ] Battle과 Shop 전환 후 Board 위치가 정상 복원되는가?
- [ ] 5×5~11×11 Board가 화면 밖으로 잘리지 않는가?
- [ ] Gold와 보유 카드가 ShopPanel에 가려지지 않는가?
- [ ] Sold 상품을 다시 구매할 수 없는가?
- [ ] 최대 인구 초과 구매와 카드 사용이 실행 전에 차단되는가?
- [ ] 구매·사용·판매 불가 상태가 DropZone 또는 버튼에서 시각적으로 구분되는가?
- [ ] 왕 판매 시 실제 데이터가 변경되지 않는가?
- [ ] Confirm·구매·판매·사용의 중복 실행이 방지되는가?
- [ ] Inspector 직렬화 필드가 모두 연결되어 있는가?

## 33. 문서 갱신 규칙

다음 경우에 문서를 갱신한다.

- 새 화면의 상호작용을 확정했을 때
- 기존 화면의 상태 전환을 변경했을 때
- 실제 구현이 명세와 다른 방향으로 확정됐을 때
- 클래스 또는 Canvas 계층 책임을 변경했을 때
- 구현 상태가 변경됐을 때

임시 픽셀 좌표, 테스트 색상, 임시 폰트 크기는 최종 스타일 작업 전까지 기록하지 않는다.
