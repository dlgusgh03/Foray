# Foray 증강 시스템 및 증강 기록

> 문서 상태: 시스템 규칙 확정 / 개별 효과는 코드 대조 필요  
> 마지막 정리일: 2026-07-18  
> 주의: 현재 대화에서 이름과 효과를 정확히 확인할 수 없는 증강은 임의로 복원하지 않았다.

---

## 1. 증강 시스템 목적

증강은 보스 클리어 후 획득하는 장기적인 런 강화 요소다.

단순한 수치 증가뿐 아니라 다음과 같은 변화를 목표로 한다.

- 기물의 행마 또는 사용법 변경
- 특정 기물 중심의 조합 유도
- 포획·배치·턴 순서 등 전투 규칙 변형
- 위험과 보상을 함께 제공
- 플레이마다 다른 전략 형성

## 2. 획득 규칙

- 보스 클리어 후 증강 후보 3개를 제시한다.
- 플레이어는 후보 중 하나를 고른다.
- 증강은 상점에서 구매하지 않는다.
- 보유 한도는 5개다.
- 보유 수가 5개 미만이면 선택한 증강을 즉시 획득한다.
- 보유 수가 5개라면 증강 교체 화면으로 이동한다.
- 새 증강을 포기할 수 있다.

## 3. 교체 규칙

1. 증강 후보 3개 중 새 증강 하나를 선택한다.
2. 기존 증강 5개와 새 증강 1개를 표시한다.
3. 교체할 기존 증강을 선택한다.
4. 확정 버튼을 누른다.
5. 확정 시 기존 증강을 제거하고 새 증강을 추가한다.
6. 새 증강 자체를 선택한 채 확정하면 새 증강 획득을 포기한다.
7. 확정 전에는 실제 보유 데이터가 변경되지 않는다.

## 4. 데이터 구조 권장 항목

각 증강은 최소한 다음 정보를 가진다.

| 필드 | 설명 |
|---|---|
| `Id` | 내부 식별자 |
| `Name` | 화면 표시 이름 |
| `Description` | 플레이어에게 보여 줄 설명 |
| `EffectType` | 효과 분류 |
| `TargetPieceType` | 대상 기물 |
| `Value` | 수치 효과가 있을 경우 값 |
| `Rarity` | 등급을 사용할 경우 |
| `Image` | 카드 및 보유 목록 이미지 |
| `Implemented` | 실제 효과 구현 여부 |

MVP에서는 `Id`, `Name`, `Description`, `Image`와 선택·교체 흐름을 우선한다.

## 5. 효과 설계 분류

### 5.1 기물 강화형

- 특정 기물의 사용 가치를 높인다.
- 예: 포획 보상, 이동 선택지 증가, 특정 조건에서 생존 또는 복귀

### 5.2 규칙 변형형

- 기존 행마 또는 전투 규칙을 바꾼다.
- 기존 메서드 내부에 예외를 무분별하게 추가하기보다 효과 정책이나 별도 판정 계층으로 분리한다.

### 5.3 조합 유도형

- 특정 기물을 여러 개 운용하거나 특정 배치를 사용할 이유를 만든다.

### 5.4 경제형

- 포획, 전투 승리, 기물 유지 등의 조건으로 골드 또는 상점 이득을 제공한다.

### 5.5 위험·보상형

- 강력한 이득과 명확한 제약을 함께 제공한다.

## 6. 현재 확인된 증강 아이디어

아래 내용은 기존 대화에서 이름 또는 핵심 콘셉트가 확인된 항목이다. 실제 `AugmentCatalog.cs`와 대조해 정확한 문구와 수치를 갱신해야 한다.

### 6.1 허수아비 왕

- **대상:** 왕
- **핵심 콘셉트:** 왕이 더 이상 움직일 수 없게 되는 대신 강한 이점을 얻는 규칙 변형형 증강
- **구현 주의:** 왕 이동 계산 메서드에 하드코딩된 예외를 계속 넣기보다, 현재 적용된 이동 정책 또는 증강 효과 판정을 통해 이동 가능 여부를 차단한다.
- **세부 보상:** 코드 대조 필요
- **구현 상태:** 효과 미확인

### 6.2 언데드 군주

- **대상:** 왕 또는 전체 군대
- **핵심 콘셉트:** 왕을 리치 왕처럼 변화시키는 언데드 테마 증강
- **시각 표현:** 짙은 회색 배경, 냉기를 연상시키는 하늘색 글자·테두리
- **세부 효과:** 코드 대조 필요
- **구현 상태:** 효과 미확인

### 6.3 포획 보상 기물 증강

- **대상:** 특정 기물
- **핵심 콘셉트:** 해당 기물이 적을 잡으면 골드를 획득
- **시각 표현:** 효과가 적용된 기물을 금색 계열로 표시
- **정확한 이름·대상·골드 수치:** 코드 대조 필요
- **구현 상태:** 효과 미확인

## 7. 증강 효과 구현 원칙

### 7.1 데이터와 효과 분리

`AugmentCatalog`는 증강의 정적 정보와 정의를 제공하고, 실제 전투 효과는 별도 계층에서 처리하는 것이 좋다.

예시 역할:

- `AugmentCatalog`: 이름, 설명, 이미지, 효과 ID
- `RunManager`: 보유 증강 목록과 획득·교체
- `AugmentEffectResolver`: 현재 증강에 따른 규칙 적용
- `MovementCalculator`: 최종 이동 정책을 전달받아 이동 계산
- `BattleManager`: 포획·턴·승패 관련 증강 이벤트 전달

### 7.2 이벤트 기반 적용 후보

다음 시점에 효과를 적용할 수 있다.

- 전투 시작
- 턴 시작
- 기물 선택
- 이동 가능 위치 계산
- 이동 직전
- 이동 직후
- 적 포획 직후
- 아군 기물 사망
- 전투 승리
- 상점 진입

### 7.3 스파게티 방지 기준

다음 상황이면 별도 효과 처리 구조를 검토한다.

- 여러 클래스에서 같은 증강 ID를 직접 비교
- 하나의 메서드에 증강별 `if`가 계속 추가됨
- UI가 직접 골드나 기물 데이터를 변경
- 증강 설명과 실제 효과 수치가 서로 다른 위치에 중복 정의됨
- 효과 제거 또는 교체 시 이전 상태를 되돌리기 어려움

## 8. UI 표시 규칙

### 보유 증강

- 보드 왼쪽에 세로 정렬
- 빈 슬롯 숨김
- Hover 시 카드 확대와 툴팁 표시
- 클릭 시 확대와 툴팁 고정
- 같은 카드 재클릭 시 해제
- 다른 카드 클릭 시 선택 전환
- 툴팁은 카드 오른쪽

### 증강 후보

- 보스 클리어 후 3개 표시
- 이름, 이미지, 설명 제공
- 카드 클릭으로 선택
- 선택된 카드 강조
- 확정 또는 건너뛰기 제공

### 증강 교체

- 기존 5개 + 새 증강 1개
- 선택과 확정을 분리
- 확정 전 데이터 변경 금지
- 새 증강 선택 후 확정은 포기 처리
