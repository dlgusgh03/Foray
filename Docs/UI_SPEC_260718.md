# Foray UI Specification

> 문서 상태: MVP UI 기준 최신 확정본  
> 마지막 정리일: 2026-07-18  
> 목적: 화면 상태, 배치, 입력 규칙, 데이터 반영 시점을 구현 전에 고정한다.

---

## 1. 공통 UI 원칙

### 1.1 MVP 우선순위

1. 화면 상태 전환
2. 필요한 데이터 표시
3. 입력 가능 대상 구분
4. 클릭·선택·확정 흐름
5. 화면 전환 시 임시 상태 초기화
6. 시각적 완성도와 애니메이션

MVP에서는 정확한 픽셀, 색상, 폰트보다 화면 계층과 상호작용을 우선한다.

### 1.2 데이터 변경 원칙

- Hover는 실제 게임 데이터를 변경하지 않는다.
- 임시 선택은 실제 게임 데이터를 변경하지 않는다.
- 구매, 획득, 교체, 배치는 확정된 동작에서만 실제 데이터에 반영한다.
- 화면을 닫거나 상태가 전환되면 임시 선택과 툴팁 상태를 초기화한다.
- UI 클래스는 `RunManager`, `Shop`, `BattleManager` 등의 시스템 메서드를 통해 데이터를 변경한다.
- 모달 또는 비전투 상태에서는 시각적 입력 차단과 `RunState` 검사를 함께 사용한다.

## 3. 기본 런 화면 레이아웃

### 3.1 공통 배치

```text
┌─────────────────────────────────────────────────────────────┐
│                               Stage / Round          Gold    │
│                                                             │
│  ┌──────────────┐        ┌──────────────────────────────┐    │
│  │ 보유 증강     │        │                              │    │
│  │ 최대 5개      │        │             Board            │    │
│  │              │        │                              │    │
│  └──────────────┘        └──────────────────────────────┘    │
│                                                             │
│  ┌──────────────┐         왕 1 | 졸 2 | 마 0 | 포 0 | 차 0   │
│  │ 보유 전술 카드│                                            │
│  │ 최대 3장      │                                            │
│  └──────────────┘                                            │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 영역별 역할

- **좌측 상단:** 보유 증강, 최대 5개
- **좌측 하단:** 보유 전술 카드, 최대 3장
- **중앙:** 현재 Board
- **Board 위:** Stage, Round
- **Board 아래:** 현재 보유 기물 종류별 개수
- **우측 상단:** Gold
- **우측 영역:** 전투 중에는 보드가 활용하고, Shop 상태에서는 상점 패널이 사용

### 3.3 고정 및 이동 기준

- 보유 증강 영역은 전투와 상점에서 같은 위치를 유지한다.
- 보유 전술 카드 영역도 같은 위치를 유지한다.
- Gold는 화면 우측 상단에 고정한다.
- Stage와 Round는 항상 Board 위에 위치하며 Board 영역과 함께 이동한다.
- 보유 기물 요약은 항상 Board 아래에 위치하며 Board 영역과 함께 이동한다.

## 4. 권장 UI 계층

```text
Canvas
├ FixedLeftUIRoot
│  ├ OwnedAugmentPanel
│  └ OwnedCardPanel
│
├ GoldHUDRoot
│  └ GoldPanel
│
├ BoardAreaRoot
│  ├ StageRoundPanel
│  ├ BoardVisualRoot
│  │  ├ BoardPanel
│  │  └ BoardUI
│  ├ OwnedPieceSummaryPanel
│  └ BattleResultPanel
│     └ ResultWindow
│
├ ShopUIRoot
├ AugmentSelectionUIRoot
├ AugmentReplacementUIRoot
├ CardSelectionUIRoot
└ AugmentTooltip
```

### 4.1 계층별 상태 변화

- `FixedLeftUIRoot`
  - 전투와 상점에서 위치 고정
  - 증강 모달 상태에서는 Dim Overlay 아래에 표시
  - 교체 상태에서는 보유 증강 카드만 Overlay 위에서 조작 가능하게 전환

- `GoldHUDRoot`
  - 항상 우측 상단 유지
  - Shop 패널이 Gold를 가리지 않아야 함

- `BoardAreaRoot`
  - Battle: 크게 표시
  - Shop: 왼쪽으로 이동
  - `StageRoundPanel`과 `OwnedPieceSummaryPanel`도 Board와 함께 이동
  - 텍스트는 필요 이상으로 축소하지 않음

- `BoardVisualRoot`
  - Battle: 넓은 영역을 사용해 Board를 크게 표시
  - Shop: Board 전체가 보이는 범위에서 축소

## 5. 전투 화면

### 목적

- 보드를 최대한 크게 표시한다.
- 플레이어가 기물을 선택하고 이동·포획할 수 있게 한다.
- 보유 증강, 전술 카드, 런 정보를 한 화면에서 확인하게 한다.

### 기본 상태

- Shop 패널 숨김
- 모달 숨김
- Board는 전투용 크기와 위치
- 선택된 기물 없음
- 이동 가능 칸 하이라이트 없음
- 플레이어 입력 가능

### Board 크기

- 전투 중에는 우측의 빈 공간까지 활용하여 Board를 크게 표시한다.
- Board는 정사각형 비율을 유지한다.
- 5×5, 7×7, 9×9, 11×11 모두 전체가 화면에 보여야 한다.
- Board 크기가 커져도 화면 밖으로 잘리지 않아야 한다.

### Board 입력

1. 플레이어 기물 클릭  
   → 기물 선택  
   → 이동 가능 칸 표시

2. 선택된 기물 재클릭  
   → 선택 해제  
   → 하이라이트 제거

3. 다른 플레이어 기물 클릭  
   → 선택 전환  
   → 이동 가능 칸 갱신

4. 이동 가능한 빈 칸 또는 포획 가능한 적 클릭  
   → 행동 실행  
   → 선택 초기화  
   → 적 턴 및 화면 갱신

5. 이동 불가능한 위치 클릭  
   → 게임 데이터 변경 없음  
   → 필요한 경우 선택만 해제

### 입력 차단

다음 상황에서는 Board 입력을 막는다.

- 전투 종료 후 결과 창 표시 중
- Shop
- AugmentSelection
- AugmentReplacement
- CardSelection
- 적 AI 행동 중

## 7. 상점 화면

### 7.1 화면 변화

Shop 진입 시 기존 화면을 제거하지 않는다.

```text
Battle
- Board 크게 표시
- Shop 숨김

Shop
- Board를 축소하면서 왼쪽으로 이동
- 우측에 Shop 패널 표시
- 좌측 증강·카드 위치 유지
- Gold 위치 유지
```

### 7.2 Board 전환 규칙

- Board는 Shop 진입 시 전투 상태보다 작아질 수 있다.
- Board는 축소와 이동 중에도 **항상 전체가 보여야 한다.**
- 일부 셀이 화면 밖으로 잘리거나 Shop 뒤에 가려지면 안 된다.
- Board의 가로·세로 비율은 유지한다.
- Shop 종료 후 다음 화면 전환 전까지 축소된 이전 전투 Board를 표시한다.

### 7.3 권장 구현 방식

- `BoardAreaRoot`는 Battle 위치에서 Shop 위치로 이동한다.
- `BoardVisualRoot`는 Battle 크기에서 Shop 크기로 축소한다.
- `StageRoundPanel`과 `OwnedPieceSummaryPanel`은 Board 위·아래 관계를 유지하며 함께 이동한다.
- Stage/Round와 보유 기물 요약 텍스트는 Board만큼 크게 축소하지 않아도 된다.
- 최종적으로는 Board가 지정된 Viewport 안에 맞도록 셀 크기를 계산한다.

```text
cellSize =
min(
    viewportWidth / boardWidth,
    viewportHeight / boardHeight
)
```

MVP 초기 구현에서는 Battle/Shop용 위치와 Scale 프리셋을 사용할 수 있다.

### 7.4 Shop 패널

- 화면 우측에 표시한다.
- Gold 아래에서 시작하여 Gold를 가리지 않는다.
- Dim Overlay는 사용하지 않는다.
- 상점 창 바깥을 클릭해도 상점을 종료하지 않는다.
- 상점 종료는 `Leave Shop` 버튼으로만 처리한다.

### 7.5 Shop 상태 입력

- Board 조작 불가
- 보유 증강 Hover·Click 확인 가능
- 보유 전술 카드 확인 가능
- Shop 상품과 버튼 조작 가능

## 8. 보유 기물 요약

Board 아래에 현재 `PlayerArmy`의 보유 기물을 종류별로 표시한다.

```text
왕 1 | 졸 2 | 마 1 | 포 0 | 차 0
```

### 갱신 시점

- 런 시작
- 기물 구매
- 기물 판매
- 증강·카드 등으로 기물이 추가 또는 제거될 때
- 런 재시작

## 9. 상점 구매 후 표시

### 9.1 기물 구매

기물 구매 성공 시:

1. Gold 차감
2. `PlayerArmy`에 기물 추가
3. 보유 기물 요약 갱신
4. 이전 전투 Board의 빈 칸 중 하나에 구매 기물을 임시 표시
5. BoardUI 갱신

### 9.2 상점용 임시 Board 배치

- 구매 기물의 실제 보유 정보는 `PlayerArmy`가 관리한다.
- 이전 전투 Board의 배치는 Shop에서 부대가 늘어난 것을 보여주기 위한 임시 표시다.
- 빈 칸 중 하나를 무작위로 선택한다.
- 가능하면 플레이어 측 배치 구역 또는 보드 하단의 빈 칸을 우선한다.
- 빈 칸이 없으면 Board에는 표시하지 않고 보유 데이터만 갱신한다.
- 다음 전투에서는 이전 Board를 폐기하므로 이 위치는 유지되지 않는다.

### 9.3 카드팩 구매

1. 카드팩 구매 성공
2. CardSelection 모달 표시
3. 카드 선택
4. 보유 카드라면 좌측 하단 `OwnedCardPanel` 갱신
5. `OnAcquire` 카드라면 즉시 효과 처리 후 보유 목록에는 추가하지 않음
6. 선택 완료 후 기존 Shop으로 복귀

CardSelection의 Hover, Click, Skip, 판매 흐름은 카드 UI 구현 전에 별도로 확정한다.

## 10. 상점 종료와 다음 전투 준비

### 흐름

```text
Leave Shop
→ 이전 전투 Board 종료
→ 다음 Stage/Round에 맞는 MapPreset 선택
→ 새 Board 생성
→ EnemyPreset 전체 배치
→ 적 기물 종류와 위치 전체 공개
→ 아군 기물을 배치 가능 구역에 일렬로 임시 배치
→ Deployment 상태 진입
→ 플레이어가 아군 배치 조정
→ 배치 확정
→ Battle 시작
```

### 화면 전환 연출

최종 연출 방향:

- 이전 Board가 왼쪽으로 이동하며 사라진다.
- 새 Board가 오른쪽에서 들어온다.
- 새 Board는 다음 전투 크기에 맞춰 표시된다.

MVP에서는 즉시 전환을 먼저 구현하고 슬라이드 애니메이션은 후순위로 둔다.

## 11. 전투 전 배치 UI

### 확정 사항

- 적 기물 종류 전체 공개
- 적 기물 위치 전체 공개
- 적 왕 위치 공개
- 아군은 플레이어 배치 가능 구역에 일렬로 초기 배치
- 플레이어가 적 배치를 본 후 아군 위치를 조정
- 배치 확정 후 전투 시작

### 구현 전 추가 확정 필요

- 클릭 후 클릭 / 드래그 앤 드롭
- 다른 아군 기물 클릭 시 자리 교환 여부
- 왕의 자유 재배치 여부
- 출전 제외 기물 처리
- 배치 완료 조건
- Confirm 버튼 활성 조건

## 12. 보유 증강 UI

### 배치

- 화면 좌측 상단
- 세로 정렬
- 최대 5개
- 빈 슬롯은 표시하지 않음

### Hover

- 카드 확대
- 카드 오른쪽에 툴팁 표시
- 툴팁에 이름과 효과 설명 표시
- Hover 종료 시 기본 상태 복귀
- 클릭 고정된 카드가 있다면 해당 카드 상태로 복귀

### Click

1. 선택되지 않은 카드 클릭  
   → 확대와 툴팁 고정

2. 같은 카드 재클릭  
   → 선택 해제  
   → 확대와 툴팁 해제

3. 다른 카드 클릭  
   → 기존 선택 해제  
   → 새 카드 선택 및 툴팁 전환

### 상태 전환

- 비전투 상태로 진입할 때 일반 선택 상태를 초기화한다.
- Shop에서는 보유 증강 확인을 허용한다.
- AugmentSelection에서는 Dim Overlay 아래에 표시하고 조작을 막는다.
- AugmentReplacement에서는 교체 대상 카드만 Overlay 위에서 조작 가능하게 한다.

## 13. 증강 선택 UI

### 진입 조건

- 보스 전투 승리 후

### 표시

- 후보 증강 3개
- 이미지
- 레어도 테두리
- 이름
- 효과 설명

### 상호작용

- Hover → 카드 확대
- Click → 즉시 선택
- 선택 강조 유지 없음
- Confirm 버튼 없음
- Skip 버튼 없음

### 선택 결과

#### 보유 증강 5개 미만

```text
후보 클릭
→ 즉시 획득
→ 보유 증강 UI 갱신
→ Shop
```

#### 보유 증강 5개

```text
후보 클릭
→ PendingAugment 저장
→ AugmentReplacement
```

### 화면 상태

- 기본 런 화면 유지
- Dim Overlay 표시
- 후보 증강 3개만 조작 가능
- Board와 기존 보유 증강 입력 차단

## 14. 증강 교체 UI

### 진입 조건

- 보유 증강 5개 상태에서 새 증강 선택

### 표시

- 기존 보유 증강 5개
- Pending 증강 1개
- Confirm 버튼
- Tooltip

### 상호작용

- 기존 증강 클릭 → 교체 대상 선택
- 다른 기존 증강 클릭 → 선택 전환
- Pending 증강 클릭 → 새 증강 포기 선택
- 한 번에 하나만 선택 가능
- 같은 카드 재클릭 시 선택 해제 가능
- 선택 없음 상태에서는 Confirm 비활성

### Confirm

#### 기존 증강 선택

```text
기존 증강 제거
→ Pending 증강 추가
→ 보유 수 5개 유지
→ Shop
```

#### Pending 증강 선택

```text
기존 증강 5개 유지
→ Pending 증강 폐기
→ Shop
```

### 중요 원칙

- Confirm 전 실제 보유 증강 목록 변경 금지
- 재진입 시 이전 선택·Hover·Tooltip 상태 초기화
- Hover 대상이 선택 대상보다 Tooltip 우선
- 확정 버튼 연속 클릭으로 중복 처리되지 않게 방지

---

## 15. 모달과 Dim Overlay

### Dim Overlay 사용

- AugmentSelection
- AugmentReplacement
- CardSelection

### Dim Overlay 미사용

- Shop

### Sorting 순서

```text
기본 런 화면
↓
Dim Overlay
↓
현재 조작 가능한 카드·패널
↓
Tooltip
```

AugmentReplacement에서는 기존 보유 증강 5개를 Dim Overlay 위에 표시하거나 별도 Sorting 구조로 조작 가능하게 한다.

## 17. UI 클래스 책임

### Panel 클래스

- 하위 UI 생성 및 표시
- 화면 단위 임시 선택 상태
- 열기·닫기
- 하위 요소 이벤트 취합

### Card / Item 클래스

- 자기 데이터 표시
- Hover·Click 이벤트 수신
- 자기 시각 상태 변경
- 상위 Panel에 이벤트 전달

### Tooltip 클래스

- 전달된 정보 표시
- 위치 및 표시 여부 관리
- 실제 게임 데이터 변경 금지

### Controller 클래스

- 화면 간 상태 흐름
- 시스템 메서드 호출
- 입력 가능 상태 관리
- 화면 전환 시 임시 상태 초기화

### Core / Manager 클래스

- 실제 게임 데이터와 규칙 관리
- 특정 UI 오브젝트 직접 참조 금지
- Unity 시각 상태에 의존하지 않음

## 18. 스파게티 방지 체크리스트

- [ ] Hover가 실제 게임 데이터를 변경하지 않는가?
- [ ] 확정 전 선택과 실제 데이터가 분리되어 있는가?
- [ ] 한 화면의 선택 상태를 여러 클래스가 중복 관리하지 않는가?
- [ ] 화면 전환 시 선택·Hover·Tooltip이 초기화되는가?
- [ ] Board 입력이 `RunState` 검사로도 차단되는가?
- [ ] Dim Overlay의 Raycast Target이 필요한 입력을 막는가?
- [ ] Tooltip이 데이터 변경 책임을 갖지 않는가?
- [ ] Shop에서 Board가 전체 표시되는가?
- [ ] Battle과 Shop 전환 후 Board 크기·위치가 정상 복원되는가?
- [ ] 5×5~11×11 Board가 화면 밖으로 잘리지 않는가?
- [ ] Gold가 Shop 패널에 가려지지 않는가?
- [ ] Confirm 또는 구매 버튼 연속 클릭이 중복 처리되지 않는가?
- [ ] Inspector의 직렬화 필드가 모두 연결되어 있는가?
- [ ] Scene 저장과 Prefab Override 상태를 확인했는가?

## 20. 문서 갱신 규칙

다음 경우에만 이 문서를 갱신한다.

- 새 화면의 상호작용을 확정했을 때
- 기존 화면의 상태 전환을 변경했을 때
- 실제 구현이 명세와 다른 방향으로 확정됐을 때
- 클래스 또는 Canvas 계층 책임을 변경했을 때
- 구현 상태가 변경됐을 때

임시 픽셀 좌표, 테스트 색상, 임시 폰트 크기는 최종 스타일 작업 전까지 기록하지 않는다.
