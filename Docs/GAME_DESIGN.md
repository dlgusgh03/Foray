# Foray 게임 기획서

> 문서 상태: MVP 기준 최신 정리  
> 마지막 정리일: 2026-07-18  
> 목적: 구현 기준이 되는 게임 규칙과 시스템 구조를 한 곳에서 관리한다.

---

## 1. 프로젝트 개요

- **프로젝트명:** Foray
- **장르:** 장기 기반 싱글 플레이 로그라이크 / 그리드 전술
- **엔진:** Unity
- **언어:** C#
- **전투 방식:** 체스처럼 칸 단위로 이동하는 2D 사각형 보드
- **핵심 목표:** 전투마다 적 왕을 처치하고, 상점·증강·카드를 통해 전력을 강화하여 런을 완주한다.
- **MVP 목표:** 핵심 런 흐름과 최소한의 UI, 플레이 가능한 30전투 구조를 완성한다.

## 2. 핵심 전투 규칙

### 2.1 승패 조건

- 적 왕을 잡으면 전투 승리
- 플레이어 왕이 잡히면 런 실패
- 체력과 공격력은 사용하지 않는다.
- 기물은 포획되는 즉시 사망한다.

### 2.2 턴 구조

1. 플레이어 턴
2. 플레이어가 기물 하나를 선택해 이동 또는 포획
3. 적 AI 턴
4. 승패 확인
5. 전투가 끝나지 않았다면 다시 플레이어 턴

### 2.3 보드

- 사각형 보드만 사용
- 장기판의 선 교차점이 아니라 체스처럼 칸을 기준으로 이동
- 스테이지가 진행될수록 보드 크기 증가

| 스테이지 | 보드 크기 |
|---|---:|
| 1~2 | 5×5 |
| 3~4 | 7×7 |
| 5~7 | 9×9 |
| 8~10 | 11×11 |

### 2.4 배치 구역

- 플레이어는 보드 아래쪽에 배치
- 적은 보드 위쪽에 배치
- 각 진영의 배치 가능 행 수는 `deployRows`로 관리
- MVP에서는 전투 전 수동 배치 UI를 추가할 예정

## 3. 기물

### 3.1 MVP 기물 종류

- 왕
- 졸
- 마
- 포
- 차

### 3.2 행마 규칙

#### 왕

- 상하좌우 및 대각선 인접 칸으로 이동
- 연결 가능한 칸만 이동 가능
- 궁성 규칙은 사용하지 않음

#### 졸

- 전진 및 좌우 이동
- 플레이어와 적의 전진 방향이 서로 반대

#### 마

- 장기의 마 행마법 사용
- 첫 직선 경로에 다른 기물이 있으면 이동 불가

#### 차

- 상하좌우 직선 이동
- 다른 기물을 통과할 수 없음

#### 포

- 이동하려면 중간에 정확히 하나의 기물을 넘어야 함
- 두 개 이상의 기물을 넘을 수 없음
- 포를 발판으로 사용할 수 없음
- 포는 포를 잡을 수 없음

## 4. 런 구조

### 4.1 전체 진행

- 총 10스테이지
- 각 스테이지는 3전투
- 총 30전투
- 표기: `1-1`부터 `10-3`

### 4.2 보스전

- 3-3, 6-3, 9-3에서 보스전
- 보스 클리어 후 증강 선택
- 보스별 특수 규칙은 정식 버전에서 확장

보스 규칙 후보:

- 같은 기물을 연속으로 움직일 수 없음
- 적 기물의 정체가 이동 전까지 보이지 않음
- 특정 구역 또는 기물에 제약 부여

### 4.3 사망 처리

- 일반 모드: 전투 중 사망한 일반 기물은 다음 전투에 복귀
- 왕 사망: 즉시 런 실패
- 영구 사망은 하드 모드 또는 특수 보스 규칙으로 추후 고려

## 5. 플레이어 군대와 인구

### 5.1 초기 군대

- 초기 최대 슬롯: 3
- 왕은 필수
- 초기 조합: 왕 1 + 졸 2

### 5.2 인구 비용

| 기물 | 인구 |
|---|---:|
| 왕 | 1 |
| 졸 | 1 |
| 마 | 1.5 |
| 포 | 2 |
| 차 | 3 |

### 5.3 슬롯 구매

- 상점에서 최대 배치 슬롯 구매 가능
- 초기 슬롯 가격은 밸런스 조정 대상
- 구매할 때마다 가격 +3
- 상점마다 슬롯 구매 항목 1개 제공

## 6. 기물 가격과 해금

### 6.1 구매 가격

| 기물 | 가격 |
|---|---:|
| 졸 | 1골드 |
| 마 | 2골드 |
| 포 | 2골드 |
| 차 | 3골드 |

### 6.2 판매 가격

- `floor(구매 가격 / 2)`
- 최소 판매 가격 1골드

### 6.3 해금

- 시작: 졸, 마
- 첫 번째 보스 클리어: 포
- 두 번째 보스 클리어: 차

## 7. 골드 경제

- 일반 전투 승리: +5골드
- 보스 전투 승리: +7~10골드
- 이자: 보유 골드 5마다 +1
- 최대 이자: +5
- 상점 리롤은 사용하지 않음

## 8. 상점

### 8.1 진입

- 전투 승리 후 상점으로 이동
- 보스전 이후에는 증강 선택 흐름이 우선될 수 있음

### 8.2 상품 구성

- 기물 상품 2개
- 슬롯 구매 1개
- 카드 상자 2개
- 리롤 없음

### 8.3 가능한 행동

- 기물 구매
- 기물 판매
- 슬롯 구매
- 카드 상자 구매
- 카드 판매
- 상점 나가기

## 9. 증강 시스템

- 보스 클리어 후 증강 후보 3개 제시
- 후보 중 하나 선택
- 보유 한도 5개
- 5개 미만이면 즉시 추가
- 5개라면 교체 화면으로 이동
- 새 증강을 포기할 수 있음
- MVP에서는 데이터와 선택·교체 흐름을 먼저 구현
- 실제 전투 효과는 이후 단계에서 순차 적용

## 10. 소모성 카드

### 10.1 획득

카드 상점을 별도로 두지 않고, 상점에서 카드 상자를 구매한다.

| 상자 | 획득량 |
|---|---:|
| 일반 상자 | 카드 1장 |
| 대형 상자 | 카드 2장 |
| 특별 상자 | 일반 또는 저주 카드 1장 |

### 10.2 보유

- 최대 3장
- 즉시 사용 카드는 획득 시 바로 처리
- 나머지는 사용 시점에 따라 구분

사용 시점 후보:

- 전투 전
- 플레이어 턴 행동 전
- 획득 즉시

### 10.3 판매

- 카드 판매 가능
- 상점이 아닌 화면에서도 판매 가능하도록 설계

## 11. 적 성장

```text
enemyPieceCount =
    3
    + (battleIndex + 1) / 2
    + (battleIndex * battleIndex) / 30
```

- `battleIndex`: 1~30
- 1-1은 약 3기물
- 후반부에는 약 30 인구 규모까지 성장
- 플레이어는 적보다 적은 수의 기물을 운용
- 진행할수록 수적 열세가 커지도록 설계

## 12. 적 프리셋

- 총 30개 프리셋
- 스테이지·라운드별 조합과 상대 좌표 보유
- 후반 프리셋은 왕 전면을 다른 기물이 보호
- 적 초기 위치는 보드 크기에 맞게 상대 좌표로 변환

## 13. 적 AI

MVP AI 우선순위:

1. 플레이어 왕을 잡을 수 있으면 포획
2. 다른 플레이어 기물을 잡을 수 있으면 포획
3. 목표와 거리가 가까워지는 이동 선택
4. 왕은 위험한 위치에서 단순 회피
5. 모든 이동은 기물 행마 규칙을 준수

정식 버전에서는 탐색 깊이 증가 또는 강화 AI를 고려한다.

## 16. 개발 원칙

- MVP 단계에서는 기능 완성을 시각적 완성도보다 우선한다.
- UI는 구현 전에 배치·기본 상태·Hover·Click·확정·취소 흐름을 먼저 확정한다.
- 임시 UI에서는 정확한 픽셀보다 영역과 계층 구조를 우선한다.
- 확정 전 임시 선택 상태가 실제 런 데이터에 반영되지 않도록 한다.
- 새 기능이 기존 클래스 책임을 과도하게 늘리면 별도 클래스로 분리한다.
